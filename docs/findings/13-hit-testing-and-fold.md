# 授权后仍未隐藏：坐标命中与排序收敛 · 2026-09-09

本轮继续处理用户反馈“图标依然没有丝毫隐藏”。旧进程已经获得辅助功能权限，却仍无法完成整理；因此继续以真实菜单栏为反馈，而不把回归通过当作实际隐藏成功。

**后续状态更新：** 用户已完成当前包授权，同包重启后确认完整接管，并验证现有两项折叠到屏外及自动收起。展开区仍存在前台应用菜单遮挡的限制；完整交互验收的最新结果见 [授权后的原生验收](14-authorized-native-fold.md)。以下保留本轮修复时的过程记录。

## 已确认的原因

1. **有效 AX 坐标不等于可操作位置。** 系统命中查询确认，左侧 TidyBar 分隔符的报告坐标实际命中了前台应用的“帮助”菜单。应用菜单会遮住左侧状态项，原代码仍按坐标发拖拽。对照中，右侧可见的 TidyBar 入口使用原手势成功双向往返。
2. **同区交换被错误当成进展。** 缩短应用菜单后，旧程序开始真实移动，但 FSMenuApp 和 OrbStack 交替执行 `3 → 1`，超过 50 次仍未完成。它们都属于始终隐藏区；被拖项虽然越过了其它元素，整体分区错误没有减少。发现后已向旧进程发送 SIGTERM，日志确认输入收尾完成。
3. **激活后的目标坐标仍会延迟变化。** 后续真机采样中，应用已经成为前台时，左分隔符仍先报告 `x=371`，随后才变为 `x=409`。旧坐标当时命中其它应用的菜单，约 0.5 秒后的新坐标才正确命中分隔符。程序此前保留了较早计算的落点，因此安全校验拒绝执行。

证据：[源坐标的系统命中](../../.build/physical-fold-20260909-2/left-divider-hit-dry.log)、[右移成功](../../.build/physical-fold-20260909-2/toggle-right.log)、[原中心落点左移成功](../../.build/physical-fold-20260909-2/toggle-left-center.log)、[旧程序整理与退出日志](../../.build/physical-fold-20260909-2/app-before-code-fix.stderr.log)。

## 修复

- 整理时临时提供短的 TidyBar 应用菜单，让被遮挡的左侧项目能够接收输入。后台 `activate` 请求在本机没有生效，已用 `NSWorkspace.openApplication` 激活当前实例；等待请求回调后再开始整理。
- 菜单借用前等待键鼠空闲。用户切换应用或 Space 时取消，恢复时不覆盖用户的新选择，也不为了整理自行切换 Space。退出先等待激活请求完成，再排空输入队列，最后恢复菜单和前台。
- 读取器保留每次观测对应的具体 AX 元素。短期 `observationToken` 固定绑定，不编码到配置，也不参与界面值相等判断；较旧的扫描不能覆盖较新的定位提示。
- 使用系统命中查询与 `CFEqual` / 有界父链验证真实投递点，拒绝应用主菜单、兄弟图标及无法确认的节点。向右的右缘落点只允许命中锚点或紧邻状态项的内边距。
- AX 查询之后重新检查取消、鼠标按住和光标位置，覆盖首次查询后、warp 之前，以及鼠标按下之前的窗口。
- 排序进展改为整条分区级别序列的逆序数严格下降。同区交换不计进展；真正改善分区的一格移动仍可继续收敛。
- 整理期间不再安排其它全量扫描；移动前从已知归属进程定向读取最新帧，减少重复全机查询。
- 投递前用同一观测绑定的 AX 元素重读目标锚点，按原插入方向重算坐标；布局尚未稳定时最多重读两次，持续不可操作则停止。
- 补充复核发现：锚点刷新可能跨屏，而显示器拓扑保持不变。移动器现在对刷新后的源点和目标点重新检查同屏，复用现有 CG → AppKit 转换，在任何输入前拒绝跨屏落点。

本轮保留 `MenuBarDropTarget` 原有的中心 / 右缘计算与鼠标抬起 flags。左侧失败不能直接推导为这些参数错误。
