## 实测发现及修复

### 退出不能用观测快照覆盖已提交布局

测试前已备份完整应用配置。实测发现，旧退出路径会把无权限扫描产生的空布局写入 committed，原有 **35 项菜单栏布局配置（隐藏 30 项、显示 5 项）** 变为空对象；部分非空扫描也有相同问题。

已删除退出时的重复布局写入。明确分配、手动排序、规则、档案和恢复操作原本就各自即时持久化；退出只负责释放可能在途的输入，并保留已有提交及 pending 状态。

已在应用退出后，从本轮启动前备份原子恢复全部 35 项及原顺序，并校验原文件字节一致。身份台账的 58 条记录语义未变，应用设置也已恢复到测试前状态。

新增回归 `passiveScansDoNotOverwriteCommittedLayoutOnExit` 覆盖无权限空扫描、有权限空扫描、部分扫描，以及用户新提交之后再出现不完整扫描的场景。该回归已先失败、再通过。

### 改名恢复不能改变顺序

退出不再覆盖原提交后，提交仍可能保留历史 ID。恢复时优先将唯一历史别名原位替换，避免把改名项追加到分区末尾。旧名已超出 8 个别名的保留上限时，仅在整个 owner 的台账、现场和旧配置关系均唯一且完整时恢复原槽位；有歧义则只恢复已知分区。

新增 `confirmedRenameKeepsCommittedOrderAcrossRestart` 和 `ownerFallbackDoesNotOverrideAnotherLedgerAssignment`，覆盖多次改名，以及多台账记录、部分 owner、多个现场项、多个旧 ID 的拒绝场景。

### 菜单、提示和性能显示

- 根菜单关闭 `autoenablesItems`，保留业务层设置的禁用状态。
- 初始降级原因区分“缺少辅助功能权限”和“拖拽机制尚未验证”。
- 空抽屉根据权限显示“请授权辅助功能”或“暂无收纳图标”。
- 性能页复用 `ResourceProbe` 的 `phys_footprint` 指标；删除 RSS 的重复采集及写死的 CPU 0% 数字。

Standards 与 Spec 限定复核均已完成，上述补充修复没有剩余审查发现。
