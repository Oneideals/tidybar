# M0 验证项 4 结论：占用与功耗

日期：2026-09-05 ｜ macOS 26.6.2 ｜ 36 个真实图标在栏（含 28 第三方）｜ 复现：`./scripts/perf-check.sh --minutes 2`、`swift run tidybar-drag-probe --repeat 30 --via-engine`

## 结论：四项预算全部达标

| 预算（报告 §4.3） | 上限 | 实测 | 判定 |
| --- | --- | --- | --- |
| 常驻内存（phys_footprint） | 40 MB | **13 MB**（静置 25s、2min 均无增长） | ✓ |
| 空闲 CPU | 0.1% | **0.0%** | ✓ |
| 启动到接管（首扫完成） | 2 s | **1.69 / 1.78 / 1.81 s**（3 次冷启动） | ✓ 但只剩 10% 余量 |
| 安装包体积 | 10 MB | **932 KB** | ✓ |
| 线程数 | 个位数 | **4** | ✓ |
| journal 收尾 | 无孤儿残留 | 仅 `layout.committed.json`，无 pending | ✓ |

主路径 30 次拖拽 **30/30 成功**（走 `LayoutEngine.apply`，含 journal 与结果复核），p50 488ms / p95 507ms，零卡键、零身份丢失。

## 这一轮顺手把测量本身的两个坑填了

**1. 测量必须走引擎入口。** 上一轮的教训落地：给拖拽探针加了 `--via-engine`，闸门现在从 `LayoutEngine.apply` 打，不再直连 mover。两条路径的差值就是主路径的真实开销：**388ms（组件）→ 488ms（引擎），约 +100ms**，来自一次 journal 写盘 + 一次结果复核前的全量枚举。直连测出的绿灯不能算通过。

**2. 引擎的结果复核此前要付两次全量枚举。** 复核"图标到底动了没有"本来会再扫一次全机器进程（实测单次 110~195ms）。新增 `MenuBarReading.items(ownedBy:)` 定向读取（协议默认实现回退全量，真实 reader 走单进程路径，几毫秒），引擎改为：**before 一次全量、after 只读归属进程**。同时也修掉了脚本里一个自伤 bug：`echo "... PID=$PID，开始计时"` —— bash 会把紧跟的全角逗号吃进变量名，导致 `perf-check.sh` 直接 `unbound variable` 退出。这类标点混进变量插值的问题已在所有脚本里统一改为 `${VAR}`。

## 内存与 RSS 的口径差异（重要，避免日后自欺）

同一进程同一时刻：`phys_footprint 13MB` vs `ps RSS 36~48MB`，差 3 倍。RSS 含 AppKit 等共享页，且**冷启动瞬间页缓存未回收时更高**（首测 48MB，静置后回落到 36MB）。预算固定用 phys_footprint；`perf-check.sh` 也已改为按它判定，RSS 只作参考打印。当初"骨架实测 48MB 超标"就是被这个口径骗了。

## 尚未达标/未覆盖的部分（不粉饰）

- **接管时延比测出来的更糟**：探针三次 1.69~1.81s 看似只剩 10% 余量，但随后打包成真 app 冒烟时同一行日志读到 **2.80s（36 图标）——已经击穿 2s 预算**。也就是说 1.7s 不是稳态而是好运。1.7~2.8s 里几乎全是"遍历 90 个进程建 AX 连接"，只扫 accessory 进程 + 并发化能压到 <1s，是进 M1 前必修的一项。
- **Energy 评级未量**：`ioreglet`/活动监视器 Energy 面板需要 GUI 读数，脚本拿不到。CPU 0.0% 是间接证据，不等价于系统能耗评级。
- **位图缓存 20MB 上限只有单测**：真实图标截图路径（`CGWindowListCreateImage`）还没接入，所以这条预算目前"代码就位、真机未证"。
- **20 图标静置 1 小时**：只跑了 2 分钟。要确认长时间无增长、无句柄泄漏（线程数稳定是好迹象但不够）。
- **主路径 +100ms 里还有一次可省的全量枚举**：before 帧也可走定向读取，前提是引擎已知归属 bundle（需要把"上一次扫描结果"做成带 TTL 的缓存，或让 apply 接受 ManagedItem 而非 itemID）。这是下一步最便宜的一次优化。
- 其他 macOS 版本（14/15）与非刘海机型未测；多显示器（负原点）只做过坐标判定，未在拖拽路径上验证。

## M0 判定

验证项 1~4 全部通过。产品闸门 `isConfirmedSupportedOS` 仍保持 false：100 次全绿是在**自造图标**上取得的，开放真实接管前需要在你自己的图标上复跑（且需你明确同意）。下一步进入 M1（P0 功能面：三分区 + 收纳面板 + 搜索 + 首启向导），同时补两个已知缺口：SIGTERM 收尾、接管时延优化。
