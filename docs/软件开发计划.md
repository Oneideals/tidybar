# Mac 菜单栏管理工具 · 产品开发报告

> 版本：v1.0（2026-09-04）
> 定位：菜单栏图标整理管家 · 泛 Mac 用户 · 原生开发 · 低占用
> 建议代号：**TidyBar**（下文以此代称）

---

## 1. 执行摘要

macOS 菜单栏图标管理是一个**成熟但正在重新洗牌**的市场。2024 年起发生了三件改变格局的事：

1. **Bartender 被资本收购（Applause Group）**，且未及时披露所有权变更，引发老用户大规模信任危机（"我的菜单栏应用悄悄换了主人"）；
2. **macOS Tahoe 26 的底层改动导致 Bartender 5/6 出现幽灵点击、光标劫持、图标错乱等严重问题**，部分十年老用户选择弃用，而竞品（含 Ice）在 Tahoe 上同样出现可靠性问题——**整个品类存在明显的质量真空**；
3. 开源免费方案中，Ice 一枝独秀（GitHub 约 29.5k star），但路线图上"条件显示、分组、布局档案"等高价值功能长期处于 Planned 状态，迭代速度跟不上用户预期；Hidden Bar 维护稀疏，Dozer 已实质停更。

**结论：当前存在一个明确的机会窗口**——用原生 Swift 开发一款"开箱即用、低内存占用、对 Tahoe/刘海屏一等公民支持、规则化自动隐藏"的菜单栏整理工具，切入 Bartender 失望用户和 Ice"等不到更新"用户这两个人群，同时以"极简上手 + 免费核心功能 + Pro 付费"覆盖泛 Mac 用户。

核心卖点（差异化主张）：

- **原生轻量**：AppKit + SwiftUI 混合，常驻内存目标 < 40 MB、空闲 CPU ≈ 0%，安装包 < 10 MB
- **Tahoe / 刘海屏一等公民**：针对 Liquid Glass 与新 Control Center 重新设计，而非补丁式兼容
- **规则引擎**：把 Bartender 最受欢迎的"触发器"（电量、Wi-Fi、时间、焦点模式）做成普通用户可理解的条件卡片，而不只是极客功能
- **透明与信任**：公开隐私声明，无遥测或仅匿名可选遥测，买断制

## 2. 市场分析

### 2.1 市场背景与需求根源

菜单栏（Menu Bar）是 macOS 上唯一一个**用户无法原生控制显隐的多图标公共区域**（系统项虽可在控制中心设置中关闭，但第三方 App 的 NSStatusItem 图标只能由 App 自身决定）。痛点来源：

| 痛点 | 说明 |
|---|---|
| 图标拥挤 | 常用 App + 常驻工具（输入法、网盘、IM、VPN）动辄 15+ 图标，小屏 MacBook 尤甚 |
| 刘海遮挡 | 2021 起 MacBook 内置刘海屏，图标会被物理遮挡，用户甚至无法看到被挡图标 |
| 专注/隐私 | 投屏、演示、截图时不想暴露图标（会议投屏露出"微信、网盘、VPN"图标是高频尴尬场景） |
| 无自动管理 | 系统不提供"图标多久没动就自动隐藏"这类能力 |

### 2.2 竞品矩阵

| 产品 | 形态/价格 | macOS 要求 | 优势 | 弱点 / 用户抱怨 |
|---|---|---|---|---|
| **Bartender 5/6** | 买断约 $16（4 周试用），Setapp 可用；v5 仅 Sonoma+ | macOS 14+ | 品类开创者，功能最全：触发器/预设、Bartender Bar、Quick Search、快捷键、分组、刘海适配、样式 | 被收购未披露引发信任危机；Tahoe 26 下幽灵点击/光标劫持/图标错乱，v6 修复不力；内存占用偏高；仅新系统 |
| **Ice** | 免费开源（GPL-3.0），GitHub ~29.5k star | macOS 14+ | 免费中功能最强：三分区（可见/隐藏/始终隐藏）、Ice Bar 下拉面板、悬停/点击/滚动呼出、拖拽排序、搜索、样式（着色/渐变/圆角）、快捷键、自动重隐藏 | 高价值功能（条件显示、分组、布局档案）长期 Planned 未交付；单人项目，迭代节奏不可控；无商业化支持 |
| **Hidden Bar** | 免费开源 | 较旧系统也支持 | 简单可靠、几乎零学习成本 | 功能极少（仅一段隐藏分隔），维护稀疏，无刘海适配 |
| **Dozer** | 免费开源 | — | 曾是 Hidden Bar 之前的代表 | **2021 年起实质停更**，已退出竞争 |
| **Vanilla** | 免费 + Pro 内购 | — | 界面精美、上手快 | Pro 功能少，更新慢 |
| **Barbee** | 低价买断 | — | SwiftUI 新写、轻量 | 生态小，功能有限 |

### 2.3 用户反馈中的高频痛点（来自评测与社区）

1. **可靠性是第一诉求**：菜单栏工具一旦出现幽灵点击、图标漂移、隐藏失败，用户会立刻卸载——它管理的是系统级 UI，容错空间极小。
2. **对 Tahoe 26 的不满横扫全品类**：Bartender 崩坏后用户尝试竞品，发现竞品也有问题，部分用户退化到"⌘ 拖拽手动删除图标"。
3. **信任与隐私焦虑**：Bartender 事件后，"菜单栏工具是否有黑箱行为"成为社区显性话题。新工具若能主动公开承诺（开源核心/无遥测），是低成本高回报的营销点。
4. **泛用户的上手门槛**：Bartender 设置项极多，普通用户被劝退；Hidden Bar 又太简陋。中间地带（"5 分钟配置完，之后忘掉它的存在"）缺乏强者。
5. **等待 Apple "Sherlocking"**：Apple 已在 Tahoe 中内置剪贴板管理器、强化快捷键，社区担心菜单栏管理被系统吞并；短期内 Apple 尚未动手，但这是中期风险。

### 2.4 机会窗口判断

- **时间窗口**：Tahoe 迁移期（现在—未来一年）是竞品口碑最弱的阶段，"Tahoe 上最稳的菜单栏工具"本身就是可传播的定位。
- **人群窗口**：Bartender 失望者（付费意愿已被验证）、Ice 等待者（对条件显示/分组有明确需求）、泛用户（想要"免费的干净 + 付费的聪明"）。
- **技术窗口**：全系第三方方案均以 macOS 14+ 为主战场，且都依赖同一套脆弱机制（辅助功能 API + 合成鼠标事件 + 窗口枚举），谁先在 Tahoe 新 API 基础上重构谁受益。

## 3. 产品定位与差异化

### 3.1 一句话定位

> **"装完即忘的菜单栏管家：默认干净，需要时聪明。"**

- 默认状态：菜单栏只留用户勾选的少数图标，其余收纳进下拉面板
- 聪明之处：按规则自动弹出（如电量低于 20% 时电池图标回到可见区）
- 存在感：正常使用中用户几乎感知不到工具本身（无弹窗、无更新打扰、低占用）

### 3.2 差异化四支柱

| 支柱 | 对标现状 | 我们的承诺 |
|---|---|---|
| 极速轻量 | Bartender 被诟病内存偏高；Ice 图片缓存上限默认 50MB | 常驻内存 < 40MB、空闲 CPU ≈ 0%、安装包 < 10MB，并在官网公开实时基准数据 |
| Tahoe 原生重构 | 竞品多为旧机制打补丁 | 基于 Tahoe SDK 重写核心布局引擎，Liquid Glass 下视觉自然融合 |
| 规则卡片 | Bartender 触发器强大但藏在深层设置 | "如果…那么…"自然语言规则卡片，普通用户 30 秒创建一条自动隐藏规则 |
| 信任透明 | 收购黑箱事件阴影 | 明确隐私声明；核心引擎考虑开源；买断制 + 明确的大版本升级政策 |

### 3.3 目标用户画像

1. **投屏党/内容创作者**：演示、录屏时需要"一键清爽"（约 30%）
2. **小屏 MacBook 用户**（Air/13" Pro）：刘海遮挡 + 空间焦虑是刚需（约 40%）
3. **重图标用户**：网盘×3、IM×4、开发工具一堆，需要分组与规则（约 30%）

## 4. 技术选型（原生开发）

### 4.1 总体架构

**语言/框架**：Swift 5.10+；UI 层 SwiftUI，窗口/面板层 AppKit（NSPanel/NSStatusItem 必须走 AppKit）。
**最低系统**：macOS 14（Sonoma）起步，**重点适配 macOS 26 Tahoe**。放弃更旧系统（Ice 已验证此策略可行，且新 API 是差异化来源）。
**分发**：Developer ID 签名 + 公证，官网直售 + Mac App Store 双轨（MAS 版需阉割依赖辅助功能高级功能的部分，做功能分级说明；或官网版为主）。

```
┌─────────────────────────────────────────────┐
│                  TidyBar                     │
├──────────────┬──────────────┬───────────────┤
│  LayoutEngine │  EventEngine │  RuleEngine   │
│  图标布局/移动  │  事件监听/呼出  │  条件触发规则  │
├──────────────┴──────────────┴───────────────┤
│           Accessibility Bridge (AX API)      │
│        + CGWindowList / ScreenCapture        │
├─────────────────────────────────────────────┤
│        Persistence (Defaults/SQLite)         │
│              UI: SwiftUI + NSPanel           │
└─────────────────────────────────────────────┘
```

### 4.2 核心技术机制（品类通行做法，均有据可依）

1. **图标识别与定位**：通过**辅助功能 API（AXUIElement）**枚举菜单栏项目、获取精确位置与状态（Ice 采用 AXSwift，验证了该路线）。
   - 权限：需要用户授予"辅助功能"权限（系统设置 → 隐私与安全性）。
2. **隐藏/移动机制**：品类通行做法是**合成鼠标事件（CGEvent 合成 ⌘ 拖拽）重排图标位置**，配合 AX 定位。
   - ⚠️ 这是全品类的脆弱点：Bartender 在 Tahoe 上的幽灵点击/光标劫持即源于此。**本项目必须实现"事件哨兵"**：每次合成事件前后校验系统光标位置与鼠标按钮状态，发现漂移立即中止并回滚布局（这是对 Bartender 教训的直接回应，也是核心工程差异化）。
3. **下拉收纳面板（对标 Ice Bar / Bartender Bar）**：无边框透明 `NSPanel`，window level 设为 `.mainMenu + 1`，锚定在菜单栏下方；通过 `CGWindowListCreateImage` 采样菜单栏底色实现动态配色（需注意屏幕录制权限提示——仅在用户开启"跟随背景色"时才触发采样，避免权限弹窗吓退用户）。
4. **事件监听**：全局事件监听（NSEvent global monitor）+ 本地监听 + RunLoop 监听三层，覆盖点击、悬停、滚动、拖拽；全部节流（Ice 默认轮询 100ms，本项目目标事件驱动为主、轮询兜底 ≥ 200ms，降低空闲 CPU）。
5. **快捷键**：优先 AppKit/CGEventTap 方案，**不用 Ice 依赖的 Carbon HotKeyManager**（已废弃，存在被移除风险）。
6. **持久化**：UserDefaults + 轻量 SQLite（规则引擎与布局档案）；图片缓存设硬上限（默认 20MB，低于 Ice 的 50MB）且内存压力时主动清空。

### 4.3 性能预算（"占用小"的硬指标）

| 指标 | 目标 | 验收方式 |
|---|---|---|
| 常驻内存（20 个图标，静置 1 小时） | < 40 MB | Instruments Allocations + 活动监视器双确认 |
| 空闲 CPU | ≈ 0%（事件驱动，无高频轮询） | 活动监视器 10 分钟采样 < 0.1% |
| 呼出/隐藏响应 | < 100ms（对标 Ice 优化后 85-150ms） | 自动化性能测试 |
| 安装包体积 | < 10 MB | 构建产物校验 |
| 冷启动到图标接管 | < 2 s | 登录项启动计时 |
| 电池影响 | 后台能耗评级"低" | Activity Monitor Energy 面板 |

工程保障：图片缓存 LRU + 硬上限；所有 AX 查询批量合并；UI 渲染 GPU 加速；禁用任何后台遥测上报（或默认关闭）。

### 4.4 主要技术风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 合成鼠标事件在系统更新后行为变化（Tahoe 已发生） | 高 | 事件哨兵 + 布局回滚；OS 版本探测，不兼容时**优雅降级为"仅下拉面板收纳"模式**（不移动图标，只提供收纳面板），保证任何系统更新下工具不至于危害用户 |
| AX API 权限引导流失 | 中 | 首启向导可视化引导；提供"无辅助功能权限"的降级模式（功能受限但可用） |
| Apple 原生吞并品类（Sherlocking） | 中 | 往"规则引擎 + 样式美化 + 分组"等 Apple 大概率不做深的层面走；保持快速跟进 |
| 屏幕录制权限弹窗吓退用户 | 低 | 颜色采样改为可选功能，默认使用系统材质色 |
| GPL 传染（若参考 Ice 源码） | 中 | **只参考思路，不复制 GPL 代码**；或整体开源（见商业化） |

| G1 | 图标健康度 | 提示"这个图标 30 天没点过，建议隐藏/卸载该 App"（延伸价值：帮用户发现后台僵尸应用） |
| G2 | 多显示器支持 | 每块屏幕菜单栏独立布局档案 |
| G3 | 智能默认 | 首启自动识别高频点击图标并建议保留（基于本地统计，不上传） |
| G4 | 样式市场 | 用户分享菜单栏样式/布局档案（在线社区内容，增强粘性） |
| G5 | 图标徽章/替代 | 用自有 StatusItem 替身显示关键信息（如合并电池+电源状态） |

### 5.4 明确不做（Scope Guard）

- ❌ 系统监控（CPU/温度/网络）——与 Stats/iStat Menus 正面竞争，偏离定位
- ❌ 剪贴板/启动器/窗口管理——Apple 已在 Tahoe 强化，Sherlock 风险最高
- ❌ iOS/iPadOS 版——菜单栏品类无对应场景
- ❌ 订阅制强制——泛用户+买断是信任策略的一部分（可选"终身+大版本"混合）

## 7. 竞争策略要点

1. **首发叙事**："在 macOS Tahoe 上最可靠的菜单栏工具"——直接收割 Bartender 危机流量；发布时同步公开 Tahoe 兼容性测试报告与性能基准。
2. **迁移友好**：一键导入 Bartender/Ice 配置（图标可见性清单），降低切换成本。
3. **可靠性优先于功能**：MVP 只做收纳不做规则，把"幽灵点击零容忍"做成品牌资产；每次系统 Beta 季（每年 WWDC 后）提前适配并发布兼容性公告。
4. **社区**：在 Bartender 相关 HN/Reddit/少数派/知乎讨论中保持技术透明（为什么图标移动在某些系统上会失效），建立"懂技术的管家"形象。
